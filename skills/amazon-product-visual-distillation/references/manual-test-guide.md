# 多模态提示词手动测试指南

一个提取版本目录至少包含 `prompt.md`、`images/template-base.png`、`images/symbols-*.png` 和 `review.md`；`prompt-text.md` 可作为可编辑原文保留。移动/复制时保持整个目录结构；图片路径相对于 `prompt.md` 所在目录。两种渠道使用**同一版本的文字和同两张图片**，各开干净会话。原商品图/设计稿只用于事后对照，不在基线重组时上传给生图模型。

## 网页生图模型（例如豆包）

1. 打开新的生图会话，选择方形输出；记录实际模型名称、日期与可见设置。
2. 上传 `TEMPLATE` 版型图和 `SYMBOLS_ORIGINAL` 符号图；确认两张图片都在消息中。网页缩略图顺序可能变化，提示词还应凭图像外观辨认角色。
3. 复制 `prompt.md` 的文字提示词粘贴生成。网页端不能访问本机相对路径，所以必须同时上传两张图片文件。
4. 保存原始生成图片和模型设置。先生成 1 张检查流程是否通；需要评估稳定性时在相同设置下再生成至至少 3 张，逐张记录，不只挑最好的一张。若平台输出带水印，记录水印来源；优先用平台提供的正式导出文件评分。

## 本地桌面 Agent（优先路径，例如 Codex）

1. 在能访问提取目录的本地项目中开一个新任务。将 `prompt.md` 的**绝对路径**发给 Agent，并要求它先读取文件，再以该文件目录为基准，实际加载文字中的 `images/...` 路径；路径字符串本身不能代替图片输入。
2. 要求 Agent 只把版型图、符号图和 `prompt.md` 复制区文字交给生图工具；原设计图仅供生成后评分。要求保存结果图、模型名称/参数和源图片路径。
3. 核对 Agent 实际读取的两张图片文件与 `prompt.md` 中记录的 SHA-256 一致；若文件被移动，先修正相对路径。
4. 和网页端一样先生成 1 张，进一步验证时用相同条件生成至少 3 张。

如果桌面 Agent 运行在别的主机而无法访问该目录，相对路径不会自动传过去；应把整个提取目录同步到它可访问的位置，或显式上传图片。

## 对照与回传

对照原图/设计稿和刀模，逐张检查：件数与实体轮廓、尺寸比例、印花区位置与占比、重复图案密度、精确文字、配色、是否出现额外物件或旧主题。参考[复测协议](evaluation-protocol.md)先判硬门槛，再给预先固定的维度评分；当前包若标 `draft`，测试结果也不可称已达 90%。

回传每一渠道的：输出图文件、模型/版本、输出尺寸、是否确实上传两张图、使用的提示词版本、参数/种子（如有）、每张图的主要偏差。不同模型结果可比较**是否遵守同一产品约束**；不能把差异全归因于“网页”或“桌面”，因为模型本身可能不同。

新符号测试要在基线后进行：保持同一 `TEMPLATE` 图和画面协议，换成经抽取/生成的新符号图与对应文字，在网页和 Agent 端都重复以上步骤，再比较符号槽外是否保持一致。
