# Gen：用已提取的产品版型和新创意生成图片

## 接口与分层

`提取包（产品数字版型） + 本次创意简报 → 新符号包 → 新主图 → 用户确认 → 新副图画面计划与图片 → 可复用提示词`。

| 层 | 管什么 | 变更规则 |
|---|---|---|
| 产品版型 | 可复用模块/部件及关系、功能、单套组成与件数、实体轮廓、比例、材质、底布/固定色、缝边/配件、已知工艺限制、可印区域和主图已核对的画面基底 | 用户只要求换主题时冻结；修改结构配置、件数或功能时建立新版型；来源未说明的生产工艺标为 `unknown` |
| 符号包 | 印在产品上的主题图形、数字、文案、可变印刷色、排布/风格、已知权利状态及印花母稿 | 根据新输入生成；一个套图共享同一符号母稿，并检查其与版型及已知工艺的适配性 |
| 画面计划 | 各图的用途、场景、道具、视角、排版、画幅和可出现的文字 | 主图遵循已核对的主图协议；副图按新主题重新创作，不能搬用原产品副图的场景图 |
| 活动语境 | 节日、促销事件、受众、情绪和视觉气氛 | 属于每次运行的数据。促销语境不会自动成为产品印花或未经核实的价格/优惠宣称 |

旧产品副图可用于核实可见结构、材质和配件，不作为新副图的背景、人物、道具布局或整体排版参考。用户明确要求复刻某张副图时，另记为不同任务及其来源；默认 gen 不复制。

## 最小输入与提问策略

先读当前对话、已提取的 `prompt.md`、产品决策和用户提供的图片/文案，自动填入已有信息；不要让用户重复回答。

1. **必须明确**：使用哪一个已提取的产品版型；本次新主题或创意是什么。只有在现有上下文无法确定时才问。参考图可直接提供主题和符号，但其中的件数、底色、场景和营销宣称不会覆盖版型。
2. **会明显影响产出量时明确**：主图、若干副图、整套图片或 A+；张数如已有项目偏好或用户刚说明则直接使用。没有任何约定时先给简洁的建议画面清单，并只对确实影响目标或成本的缺项提问。
3. **可选覆盖项**：用户指定某个副图需要尺寸图、材质图、场景图，或限定元素、颜色、文字、节日、活动、渠道时遵从；没指定时按产品事实与营销目标规划，不逐项问卷。场景地点、道具、机位、光线和排版通常由 Agent 提出方案并在 `scene-plan.md` 标为 `inferred`，不因这些创意细节未指定就暂停。仅当用户要求的画面必须依赖某项未核实的商品事实、特定人物/场所授权或会改变产品身份的选择时，集中询问关键缺项。
4. **事实冲突**：新参考图与版型的件数、尺寸、材质或底色冲突时，默认只抽取用户要求的可变符号。若用户要把冲突项变成新产品事实，需明确新版型。无法核实的功能/尺寸/性能声明不进入图片文字；可改用不含该声明的画面。

把上述结果写成短 `brief.md`，标注每项的来源、`confirmed / inferred / disputed / unknown`。用户已经授权生成且没有关键冲突时，直接做到新主图候选；主图须单独由用户确认，确认后的副图无需再逐张重复请求批准，除非用户另有要求。

## 生成顺序

1. **冻结依赖**：记录提取包版本、版型图哈希、实体/印花槽和原主图画面协议。主图使用已核对版型；不因参考图是不同套装而改变原版型。创建独立新主题版本目录，不覆盖提取包。
2. **抽取新符号**：把参考图中的实际印花图案、精确文字、允许变化的印墨颜色写成逐槽文字；另将活动背景/场景创意与产品印花分开。图像模型生成统一的符号图、必要的展开印花母稿、主图配准图和配件印花。全部与来源及文字核对，错误资产保持草稿并重生。
3. **先做新主图**：主图以冻结空白版型和新配准图作输入，优先在可印区域编辑。对照原主图和新符号要求作内部复测，保留提示词、输入角色、模型/可见设置、图片和哈希。将候选图、评分、具体偏差和绝对路径交给用户；用户可提出意见，逐轮修改主图及对应符号/提示词。逐轮记录用户原话、采纳的改动、候选图路径及哈希、评分和决定；新轮次用递增版本或运行编号，不覆盖旧图。只有用户明确确认**当前候选图及其版本**，才把确认记录与该图哈希绑定，标记 `main_approved` 并进入下一步。模型自行评分达标不替代用户确认；等待期间不能提前设计或生出正式副图。
4. **确认后规划副图**：按用户指定的张数，为每张写目的、主视觉、商品可见面、必要物件、背景/道具、文字及其事实来源、画幅。副图相互补足产品信息，并围绕新主题重新设计场景/排版；同一套装、布色、印花和配件在各图一致。某项规格未核实就改用其他画面，不编造数字。A+ 是独立模块计划，不混入轮播图。
5. **生副图并复测**：副图以已确认主图的产品身份、产品版型、新印花母稿和本次新画面计划作输入，不能把原产品副图当场景底图。各图生成前固定硬门槛和权重，逐图核查产品事实、新符号、场景目标及套图一致性；错字、漏件、改底布、旧符号残留或复制旧副图场景等硬错误直接失败，整套不以平均分掩盖单图失败。失败时修改对应层并留存历史。每张记录实际提示词、输入/输出哈希、模型/可见设置；模型版本或种子不可见时记 `unavailable`，不承诺像素级重复生成。概念视觉通过不等于实物或上架审核通过。

## 交付与追溯

一个版本目录至少含 `brief.md`、一个可复制的 `prompt.md`、其相对引用的 `images/`、已完成阶段的 `outputs/`、实际调用/输入/输出记录及 `review.md`。用户确认前的包只交付主图候选及主图提示词，并标 `pending_user_main_approval`；确认后才补逐张副图画面计划与副图输出。桌面 Agent 必须读取图片文件作为多模态输入。输出图不是下一轮的产品事实，除非用户把它确认成新的设计基线。

记录上游提取包版本、来源 ID、每张参考图的角色、MIME、SHA-256、所有提示词、模型/可见参数、每次输出哈希、人工评分及修改原因。这样可以复原**输入、决策与操作过程**；随机生图模型未提供种子或固定版本时只能复测，不能保证重新运行得到逐像素同一图。
